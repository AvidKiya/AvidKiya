# Fix Cloudflare Pages Build Failure

## Problem

Build fails with `Error: DATABASE_URL is required` because:

1. `src/db/index.ts:4-8` reads `process.env.DATABASE_URL` at **module scope** and throws if undefined
2. All 6 API routes `import { db } from '@/db'` at the top level, triggering the throw during `next build`'s page data collection
3. `export const dynamic = 'force-dynamic'` does **not** prevent module evaluation during build
4. `pg` (TCP sockets) is incompatible with Cloudflare Workers/Pages runtime — even if the build passed, the app would crash at runtime
5. The deployer (`deployer.js:199`) already provisions an `AVIDKIYA_KV` Cloudflare KV namespace but it's never used by the app

## Solution: Replace `pg` + Drizzle with Cloudflare KV

The app is a pure key-value store (all routes do `getKV(key)` / `setKV(key, value)` via raw SQL). Cloudflare KV is the natural fit — native, zero external dependencies, already provisioned by the deployer.

## Changes

### 1. Install `@cloudflare/next-on-pages`, remove `pg`/Drizzle deps

```bash
npm install @cloudflare/next-on-pages
npm uninstall pg dotenv drizzle-orm drizzle-kit @types/pg
```

### 2. Create `wrangler.toml` (new file)

```toml
compatibility_date = "2024-09-01"
compatibility_flags = ["nodejs_compat"]

[[kv_namespaces]]
binding = "AVIDKIYA_KV"
# Set this to your actual KV namespace ID from the Cloudflare dashboard
id = "YOUR_KV_NAMESPACE_ID"
```

### 3. Rewrite `src/db/index.ts`

Replace the pg pool + Drizzle with CF KV accessor functions via `getRequestContext()`:

```ts
import { getRequestContext } from "@cloudflare/next-on-pages";

export async function getKV(key: string): Promise<string | null> {
  const { env } = getRequestContext();
  return env.AVIDKIYA_KV.get(key);
}

export async function setKV(key: string, value: string): Promise<void> {
  const { env } = getRequestContext();
  await env.AVIDKIYA_KV.put(key, value);
}
```

`getRequestContext()` is only callable at request time (inside route handlers), so no build-time module evaluation issues.

### 4. Delete `src/db/schema.ts`

Unused — no file imports `kvStore` from this Drizzle schema.

### 5. Update all 6 API routes

Remove the duplicated local `getKV`/`setKV` functions (identical in 5 routes), remove `import { db } from '@/db'` and `import { sql } from 'drizzle-orm'`, replace with `import { getKV, setKV } from '@/db'`.

| Route | Change |
|-------|--------|
| `src/app/api/change-password/route.ts` | Remove lines 1-2 imports, 6-21 local helpers. Import `getKV, setKV` from `@/db` |
| `src/app/api/cms/route.ts` | Same — remove lines 1-2, 9-24. Import shared `getKV, setKV` |
| `src/app/api/comments/route.ts` | Same — remove lines 1-2, 7-22 |
| `src/app/api/messages/route.ts` | Same — remove lines 1-2, 7-22 |
| `src/app/api/verify/route.ts` | Remove lines 1-2, 6-14. Import only `getKV` from `@/db` |
| `src/app/api/health/route.ts` | Replace with simple `return Response.json({ ok: true })` — no DB check needed |

### 6. Update `package.json` build script

Change `"build": "next build"` to `"build": "npx @cloudflare/next-on-pages"` (matching what the Cloudflare Pages deployment already uses).
